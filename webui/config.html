SkillOpt Self-Evolution Engine

The bot learns from every task you run and improves its own skills in the background. Toggle the settings below and click Save — your values are written to disk and applied immediately.

Auto-loop — background daemon, no manual steps needed

When ON, the plugin periodically harvests rollouts, runs a direct optimizer cycle, and (if auto-adopt is also ON) promotes improvements that pass the validation gate.
Whether improvements are applied automatically is now the Evolution mode setting below.

What autonomous mode does, and what still stops it
  • Changes that pass every gate are written into live SKILL.md files without asking you. Each write is snapshotted, so it can be rolled back.
  • At most autonomous adoptions per day, and per skill per day.
  • A proposal needs at least rollouts of evidence before it can be adopted automatically.
  • Post-adopt verification is .
  • Every autonomous change is recorded in logs/runs/governance.log as decided_by: autonomous, permanently distinguishable from your own decisions.
  • Never bypassed by autonomy: a skill's .skillopt.optout marker, immutable mode, the pause marker, the minimum interval between cycles, or the daily cost budget.
To freeze autonomy without changing this setting, create logs/runs/.autonomous_pause. To stop a single skill, pause it in the Governance card below, or write .skillopt.optout in its skill directory.

Governance — auto opt-in behind a human-approval gate

New skills seen in rollouts are auto-opted-in with require_human_approval: true — they stay pending until you Approve them here. Immutable or opted-out skills are never touched. Backend

The optimizer LLM is separate from the agent's chat LLM. Set AZURE_OPENAI_API_KEY / ANTHROPIC_API_KEY in your env, or run the skillopt_setup tool once to auto-translate A0's existing env vars.

Rollout privacy

Best-effort protection for new rollouts, direct model prompts, the official-engine bridge, and real replay. This does not detect every secret or personal detail. Arguments and results are excluded by default. When enabled, common credential patterns are still redacted if redaction is on. Existing rollout files are not rewritten. Expiry removes only top-level JSON files in SkillOpt's logs/rollouts directory during an auto-loop tick. It does not clean bridge caches or run history. Effective: redaction ; args ; results ; retention days.

Paired replay report

Without a manifest, reports descriptively on gate pairs. To use an independent reviewed set, enter an absolute JSON file path containing a list of {"id":"stable-id","task":"task text"} records. Keep those tasks out of optimization rollouts. Independent replay uses real A0 runs and can incur extra model cost. Reports never change the gate or adoption result.
